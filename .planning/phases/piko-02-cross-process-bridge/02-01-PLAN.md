<objective>
Close the two real correctness gaps 02-RESEARCH.md found in the already-working `DarwinChannel`
skeleton — a session-scoped sequence-number bug that silently drops every draft after the first
capture session, and a missing `deinit` that leaks Darwin notify center observers — and back both
fixes with a new `PikoBridgeTests` target. This is NOT new IPC infrastructure: the Darwin
notification + App Group JSON channel already exists and already works end to end; this plan
hardens its two contract/lifecycle gaps and adds the test coverage BRDG-01 through BRDG-04 need.

Purpose: the sequence bug is invisible in a single-session smoke test but breaks every second
dictation in the same keyboard-extension process lifetime — it must be closed before Phase 4
builds streaming insertion on top of `CaptureDraft`. The observer leak is latent today but becomes
a real dangling-pointer risk the moment more than one `DarwinChannel` is constructed per process,
which is exactly what the BRDG-03 reconnection test below does 20 times over.
Output: `sessionEpoch` + `isNewer(than:)` on `CaptureDraft`, a `deinit` on `DarwinChannel`, a new
`PikoBridgeTests` target in `Package.swift`, and three new test files
(`SequenceOrderingTests.swift`, `ReconnectionSurvivalTests.swift`, `RoundTripLatencyTests.swift`).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| App Group JSON files (`draft.json`/`state.json`/`result.json`) | Written by one process, read by another — same-app trust level, different process; carried forward from Phase 1 (T-piko01-01), unchanged by this phase |
| Darwin notify center observer registration/removal lifecycle | An unretained `self` pointer is registered as a C callback observer in `observeAll()`; it must be deregistered before deallocation or the pointer dangles the instant a second channel outlives the first |
| `CaptureDraft` session/sequence ordering contract | The rule both processes must agree on for "what counts as stale data" — a shared-type concern (`PikoKit`), not per-consumer duplicated logic |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|--------------|-----------------|
| T-piko02-01 | Tampering | `CaptureDraft.sessionEpoch`/`sequence` ordering | mitigate | Task 1 adds `sessionEpoch` + `isNewer(than:)` pair comparison, closing the "stale data mistaken for current" gap; regression covered by `SequenceOrderingTests`, including the literal `(0, 47)` vs `(1, 0)` regression case |
| T-piko02-02 | Denial of Service | `DarwinChannel` Darwin notify center observer lifecycle | mitigate | Task 2 adds `deinit` removing the observer registration before deallocation, preventing a dangling-pointer callback invocation; regression covered by `ReconnectionSurvivalTests`' 20-iteration construct/discard loop |
| T-piko02-03 | Tampering | App Group JSON files (`draft.json`/`state.json`/`result.json`) | accept | Same as Phase 1's `T-piko01-01` — malformed/truncated JSON from a killed mid-write is already surfaced as a decode failure (`nil`) by `DarwinChannel.read(_:)`'s `try?`; no change in this phase, risk carried forward unchanged |
</threat_model>

<objective>
Build the keyboard extension's UI shell and wire the mic button to the armed session via
`SessionChannel`. This plan delivers the "remote control" half of BRDG-01 — the keyboard can
trigger capture start/stop and reflect session state, even though no real transcription exists
yet (that's Phase 5's `PikoTranscribe`).

Purpose: The keyboard extension is the user's primary interaction surface for dictation — they
see and tap it, not the container app. Getting the signal flow correct now (mic tap → Darwin
notification → app receives signal) validates the Phase 2 bridge under real keyboard-to-app
conditions. The UI also provides visual feedback that the armed session is live, preventing
frustrating "nothing happened" taps when the app has backgrounded or died.

Output: A SwiftUI-based keyboard layout (`KeyboardView`) with a working mic button
(`MicButton`), embedded in `KeyboardViewController` via `UIHostingController`. Signal posting
and state observation are tested against `MockSessionChannel` to prove correctness without
requiring a running container app.
</objective>

```swift
// Mic button tap logic
func micButtonTapped() {
    guard let state = sessionState, state.isLive() else {
        // App not armed — show "open Piko app" prompt
        return
    }
    switch state.phase {
    case .armed:
        channel?.post(.captureStart)
    case .capturing:
        channel?.post(.captureStop)
    default:
        break
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keyboard → App | Darwin notification + App Group file; keyboard sends signals, app trusts them as user intent |
| App → Keyboard | SessionState written to App Group; keyboard trusts heartbeat/phase values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | Darwin notification names | accept | Signals are fire-and-forget doorbells with no payload; spoofing them only triggers state reads, not data exfiltration |
| T-04-02 | Tampering | SessionState JSON in App Group | accept | File is in a sandboxed App Group container; only Piko processes can write it |
| T-04-03 | Information Disclosure | SessionState fields | accept | Contains only phase, heartbeat, skin, profile — no PII, no secrets |
| T-04-04 | Denial of Service | Rapid signal posting | mitigate | App's signal handler is async for-await loop; rapid posts queue, don't crash |
</threat_model>

<objective>
Fix the three compile/contract blockers 07-RESEARCH.md identified before any real ActivityKit code
can be written, and resolve the open-question decision on what the widget's stop button does: post
the existing `Signal` enum with one new case, handled by the existing `CaptureCoordinator.handleSignal`
switch, reusing `DarwinChannel` unchanged.

Purpose: `PikoAttributes`/`ContentState` currently live inside `App/PikoWidgets`, an app-extension
target the container app cannot import — Plan 07-02's `LiveActivityController` would not compile
without this move. `SessionPhase`/`Skin` lack `Hashable`, which `ActivityAttributes` requires —
this fails silently until the type is used in a real `Activity<Attributes>` call. And there is no
cross-process signal today for "the widget wants the whole session stopped, not just capture" —
`Signal.stopRequested` is that signal, and `CaptureCoordinator` (which already privately holds
`session`) is where the app-side reaction belongs, exactly the way `AppComposition`'s existing
`for await signal in channel.signals` loop already reaches every signal by forwarding to
`captureCoordinator.handleSignal(signal)` unconditionally — no change to that loop is needed, only
to the switch inside `handleSignal`.

Output: `PikoKit` exports a `Hashable`-conformant `PikoAttributes`/`ContentState` pair; `Signal` has
a sixth case; `CaptureCoordinator` reacts to it by stopping capture (if live) then disarming.
</objective>

Current `App/Piko/CaptureCoordinator.swift` `handleSignal` (verbatim):
```swift
public func handleSignal(_ signal: Signal) async {
    switch signal {
    case .captureStart:
        do {
            try await startCapture()
        } catch {
            print("CaptureCoordinator: startCapture failed: \(error)")
        }
    case .captureStop:
        await stopCapture()
    default:
        break
    }
}
```
`CaptureCoordinator` already stores `private let session: SessionCoordinator` (constructor
parameter, set in `init`) — no new property needed to reach `session.disarm()` from this switch.
`channel.readState()?.phase` is the existing, already-used pattern for reading current phase
without a synchronous accessor on `SessionCoordinator` (see `stopCapture()`'s own
`channel.readState()?.profile ?? .message` two lines below the switch).

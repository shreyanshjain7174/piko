<objective>
Wire the real `SQLiteMemory` (Plan 08-02) into the running app: `AppComposition` constructs it
once against an app-private `Application Support` path, and `CaptureCoordinator.stopCapture()`
records every finished `CaptureResult` into it — the one new line `HIST-01` needs, placed at the
exact call site `08-RESEARCH.md`'s Pattern 4 specifies (immediately after the existing
`channel.writeResult(result)`/`channel.post(.resultReady)` pair, before `onTidyingChange?(false)`),
matching the "finalize once, fan out to every interested consumer" shape Phase 7 already
established in this same function for `onTidyingChange`.

Purpose: `CaptureCoordinator` is the only place a `CaptureResult` is produced; `ArmView`'s history
list (Plan 08-05) is the only place one is read back. Storage lives in the container app's own
`Application Support` directory — not the `group.dev.piko.shared` App Group every other piece of
cross-process state (`draft.json`/`result.json`/`state.json`) uses — because no other process
(keyboard extension, widget extension) ever needs to read history back; widening the App Group's
contents for a requirement that doesn't exist would be copying a pattern past the point it applies.

Output: `CaptureCoordinator` gains a `memory: any Memory` dependency and calls `memory.record(_:)`
on every completed capture; `AppComposition` constructs the one real `SQLiteMemory` instance the
whole app shares, unconditionally on both Simulator and device.
</objective>

`App/project.yml`'s `Piko` app target already lists `PikoMemory` in its linked products (verified

**Do not gate `SQLiteMemory` behind `#if targetEnvironment(simulator)`** the way
`transcriber`/`brain` are gated above. Those two are gated because `SpeechTranscriberEngine`/
`SystemBrain` depend on hardware/entitlements unavailable in Simulator. `SQLiteMemory` has no such
dependency — it is fully testable and usable on Simulator (Plan 08-02's own test suite already
exercises it purely via `swift test`, no device). Gating it would introduce an unverified-on-device
gap where none needs to exist — `08-RESEARCH.md` explicitly names this as the one anti-pattern to
avoid, and flags Phase 8 as meant to be the first fully-closeable phase (unlike Phases 3/7's
transcriber/brain/ActivityKit device-only gaps).

**Application Support path construction** (the exact, real `FileManager` API to use, not a
hand-rolled path):
```swift
let appSupportURL = try! FileManager.default.url(
    for: .applicationSupportDirectory, in: .userDomainMask,
    appropriateFor: nil, create: true)
let dbURL = appSupportURL.appendingPathComponent("history.sqlite")
```
`try!`/force-unwrap here matches this exact file's own existing idiom (`let channel =
DarwinChannel()!` two lines above) — a failure here is a truly exceptional, unrecoverable
filesystem condition at app launch, and crashing immediately is preferable to running with a
silently broken history feature; this is a deliberate, consistent choice, not a shortcut.

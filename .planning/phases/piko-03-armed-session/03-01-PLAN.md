<objective>
Give `PikoAudio` its first real `ArmedSession` conformer: a `SessionCoordinator` that owns
`AVAudioSession`/`AVAudioEngine` and implements `arm()`/`disarm()`/`startCapture()`/`stopCapture()`
per the protocol that already exists unchanged in `Sources/PikoAudio/ArmedSession.swift`. This is
NOT a new protocol — `03-RESEARCH.md` confirms `ArmedSession` already matches the roadmap's plan
hint exactly. This plan's job is the first real implementation, plus the two things that make it
real rather than theoretical: a platform guard so the rest of the package keeps building on macOS,
and a composition root so a person can actually tap a button in the app and arm a session.

Purpose: SESS-01 ("user can arm a session from the container app") is the phase's first, most
foundational requirement, and everything Plan 03-02 (interruption recovery) and Plan 03-03 (Back
Tap/Action Button) build on. Getting the platform guard right here, before any `AVFAudio` code
lands, is what keeps `swift build`/`swift test` — the command every prior phase's plan has
verified against — from breaking the moment this phase starts, per `03-RESEARCH.md` Pitfall 3.
Output: `SessionCoordinator.swift`, `InterruptionSource.swift` (the contract Plan 03-02's real
production conformer will implement, plus a permanent `NullInterruptionSource` placeholder this
plan's own composition root uses until 03-02 lands), a new `PikoAudioTests` target, and a
concretely reachable "Arm" button in `App/Piko`.

public protocol ArmedSession: Sendable {

    - `@MainActor public final class SessionCoordinator: ArmedSession`. Mark it `@MainActor`
      rather than hand-rolling a lock (unlike `DarwinChannel`'s `@unchecked Sendable` + `NSLock`
      pattern) because every legal caller of `arm()`/`disarm()`/`startCapture()`/`stopCapture()`
      is already UI-driven (a button tap, or — in Plan 03-03 — an `AppIntent.perform()`, which
      Swift's App Intents runtime also drives from a context compatible with `MainActor` hops);
      `@MainActor` isolation gives the class implicit, compiler-checked `Sendable` conformance
      under Swift 6.2 strict concurrency with no manual synchronization code, which is simpler and
      safer than replicating `DarwinChannel`'s lock for a type with no cross-thread hot path.
    - Stored properties: `private let channel: any SessionChannel`, `private let interruptions:
      any InterruptionSource`, `private let isForeground: @MainActor @Sendable () -> Bool`, `private var
      sessionEpoch = 0`, `private var currentPhase: SessionPhase = .idle`, `private var
      heartbeatTask: Task<Void, Never>?`, `private let phaseContinuation:
      AsyncStream<SessionPhase>.Continuation`, `public let phase: AsyncStream<SessionPhase>`.
    - `public init(channel: any SessionChannel, interruptions: any InterruptionSource, isForeground:
      @escaping @MainActor @Sendable () -> Bool)` — no default value for `isForeground`. This is a
      deliberate, non-obvious design choice worth flagging explicitly in this plan (it is not
      dictated by 03-RESEARCH.md, which left the exact foreground-check mechanism unspecified):
      giving `isForeground` a default of `{ true }` would make it silently easy for a future call
      site to construct a `SessionCoordinator` that always reports itself as foreground-legal,
      quietly defeating the one compile-time-enforceable trace of CONSTRAINTS.md C2 this class
      has. Requiring every call site (composition root, every test) to explicitly supply the
      closure keeps that C2 obligation visible at every construction site instead of buried behind
      a default. Rejected alternative: a dedicated `ForegroundState` protocol mirroring
      `InterruptionSource` — rejected because there is exactly one query (`Bool`, not a stream of
      events), so a protocol adds a type for no behavior a closure doesn't already provide;
      02-RESEARCH.md and this phase's own research consistently prefer the smallest seam that
      makes the behavior testable, not the most uniform one. The closure is typed `@MainActor
      @Sendable`, not plain `@Sendable` — Task 3's composition root implements it as
      `{ UIApplication.shared.applicationState == .active }`, and `UIApplication` is MainActor-
      isolated under this project's `SWIFT_STRICT_CONCURRENCY: complete` setting (`App/project.yml`);
      a plain `@Sendable () -> Bool` cannot legally call a MainActor-isolated getter. Since every
      real call site (`arm()`, itself `@MainActor`-isolated) only ever invokes this closure from
      `SessionCoordinator`'s own actor, marking it `@MainActor` costs nothing at any call site and
      avoids a genuine compile failure a plain `@Sendable` closure would hit.
    - In `init`, set `(phase, phaseContinuation) = AsyncStream.makeStream()`, then start consuming
      `interruptions.events` in a `Task` stored nowhere (fire-and-forget is fine here — it lives
      exactly as long as the coordinator does, since `@MainActor` classes are reference types and
      the task closure captures `self` weakly to avoid a retain cycle) that awaits each
      `InterruptionEvent` and, on `.began`, `.routeChanged`, or `.lowPowerModeChanged(enabled:

      beyond that shared "always recover to idle" behavior. On `.ended(shouldResume:)` and
      `.lowPowerModeChanged(enabled: false)`, do nothing (leave phase as-is) — re-arming after an
      interruption ends is a user-initiated action per 03-RESEARCH.md's Open Question 1
      recommendation (no new `SessionState` field, no auto-resume), which Plan 03-02 revisits if
      research's assumption proves wrong on device.
    - `arm() async throws`: guard `isForeground()` is true, else `throw PikoError.notForeground`.
      Bump `sessionEpoch += 1` (unused by this plan directly, but a future consumer — e.g. tagging
      `CaptureDraft.sessionEpoch` at capture start — needs a monotonic counter scoped to "since
      this coordinator was armed most recently"; keeping it here now avoids a second migration
      later). Activate the audio session: obtain `AVAudioSession.sharedInstance()`, call
      `try session.setCategory(.playAndRecord, options: [.allowBluetoothHFP])` then `try
      session.setActive(true)` — do not force-try either call; let both propagate as thrown
      errors out of `arm()` so a caller sees a real error rather than a crash, per CLAUDE.md's
      no-force-unwrap rule and this plan's own threat model below. Flag the exact category/option
      constants as flagged `[LOW confidence]` in 03-RESEARCH.md's own words — verify
      `.allowBluetoothHFP` is the current, non-deprecated constant against the `apple-docs` MCP
      server or current documentation before treating it as final, per `docs/WORKING-AGREEMENT.md`
      item 2; if it has been renamed or removed in the current SDK, use the correct current
      equivalent and note the correction in SUMMARY.md. On success, set `currentPhase = .armed`,
      yield it to `phaseContinuation`, call `channel.writeState(SessionState(phase: .armed,
      heartbeat: .now))`, and start the heartbeat task (a `Task` looping `try? await
      Task.sleep(for: .seconds(2))` then re-writing `SessionState(phase: currentPhase, heartbeat:
      .now)` via `channel.writeState`, forever, until cancelled). If `setCategory`/`setActive`
      throws, do not change `currentPhase` and rethrow the error — `arm()` must leave the
      coordinator in its prior state on failure, not a half-armed one.
    - `disarm() async`: cancel and nil out the heartbeat task, call `try?
      AVAudioSession.sharedInstance().setActive(false)` (best-effort — deactivation failing is not
      worth propagating as a thrown error since the coordinator is returning to idle regardless),
      set `currentPhase = .idle`, yield it, and call `channel.writeState(SessionState(phase:
      .idle, heartbeat: .now))`.
    - `startCapture() async throws`: guard `currentPhase == .armed` else `throw
      PikoError.notArmed`. Set `currentPhase = .capturing` and yield it. (This plan does not wire
      a real `AVAudioEngine` tap/buffer pipeline — that is `PikoTranscribe`'s job in Phase 5 per
      ROADMAP.md; this phase's job is the phase transition and lifecycle correctness, not audio
      buffer plumbing consumed by a transcriber that doesn't exist yet.)
    - `stopCapture() async`: set `currentPhase = .armed` (not `.idle` — stopping a capture leaves
      the session armed for another capture, matching `SessionPhase`'s own case ordering
      idle→armed→capturing→tidying) and yield it.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
